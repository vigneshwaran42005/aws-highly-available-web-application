AWS-Based Highly Available Web Application
1. VPC & Network Infrastructure

Designed and configured an AWS VPC with a secure public and private network architecture.

AWS components used:

Amazon VPC
Public Subnets
Private Application Subnets
Private Database Subnets
Availability Zones
Internet Gateway
NAT Gateway
Route Tables

Purpose:
To create a secure, organized, and highly available cloud network by separating public-facing and private resources.

2. Bastion Host

Configured a Bastion Host in the public subnet to securely access the private Windows EC2 instances.

Local Computer
      ↓
Bastion Host
      ↓
Private EC2

Skill demonstrated:
Secure access to private infrastructure using a jump server/Bastion Host.

3. Two Private EC2 Application Servers

Deployed two Windows EC2 instances in separate Availability Zones.

EC2-A → Private Subnet → AZ-A


EC2-B → Private Subnet → AZ-B

Both instances were configured to host the application.

Purpose:
To provide redundancy and improve application availability.

Skills demonstrated:

Amazon EC2
Windows Server
Private Subnet Deployment
Multi-AZ Architecture
4. IIS Web Server

Installed and configured IIS (Internet Information Services) on both Windows EC2 instances.

Created separate test pages:

EC2-A → Server A Page


EC2-B → Server B Page

This was used to verify that both application servers were working correctly before integrating the application.

Skills demonstrated:

IIS
Windows Server Administration
Web Server Configuration

7. Amazon Aurora PostgreSQL

Created Amazon Aurora PostgreSQL as the database layer.

Configuration:

PostgreSQL
Port: 5432
Private database access
Writer Endpoint
Reader Endpoint
Database hosted within the private network

Public access was disabled to prevent direct Internet access to the database.

Purpose:
To provide a secure and managed relational database for storing student information.

Skills demonstrated:

Amazon Aurora
PostgreSQL

Private Database Architecture
8. Security Groups

Implemented Security Groups to control communication between the different layers.

Internet
   ↓
ALB : 80
   ↓
EC2 : 80
   ↓
Aurora : 5432

The database Security Group allows PostgreSQL traffic only from the application EC2 Security Group.

ALB-SG
   ↓
EC2-SG : Port 80
   ↓
Aurora-SG : Port 5432

The database was not exposed directly to the Internet.

Skills demonstrated:

AWS Security Groups
Network Security
Access Control
Private Database Security
Least-Privilege Network Access
9. EC2 → Aurora Connectivity Testing

Verified connectivity between the private EC2 application server and Aurora PostgreSQL using:

Test-NetConnection <Aurora-Endpoint> -Port 5432

The connectivity test returned:

TcpTestSucceeded : True

This confirmed that the private application server could successfully communicate with the Aurora PostgreSQL database over port 5432.

Skills demonstrated:

Network Troubleshooting
TCP/IP
PostgreSQL Connectivity
AWS Security Group Troubleshooting
10. Student Data Storage

Implemented database storage through the Flask backend.

The application follows this flow:

Student Form
     ↓
Flask Backend
     ↓
INSERT Query
     ↓
Aurora PostgreSQL
     ↓
student_details

Example database record:

ID | Name    | Standard | Roll No
---|---------|----------|--------
1  | Vignesh | 12th     | 101

The UI is designed primarily for data entry, while the student records are stored securely in the backend database.
